# Satr roadmap

A to-do roadmap for the complete Satr editor. The original product decisions and phased work are retained below, with actionable items expressed as task checkboxes. Mermaid is postponed until the core editor and preview are stable.

## Current status (October 2026)

Satr runs as a web app (Vite + TypeScript + CodeMirror 6) and as an Android app
(Capacitor 7, `android/`, with Satr's own print, storage, system-bars and
open-file plugins). **0.16.0.** Notes are files in folders behind one storage
interface: a virtual file system in localStorage on the web, and the device's
own files in the app. GitHub Actions builds a signed debug APK for each `v*`
tag, signed with one fixed key so every build installs over the last.

### Done

Editor
- [x] CodeMirror editor: per-line RTL/LTR, line numbers, soft wrap, list continuation (Persian digits too)
- [x] Live preview in the editor (Obsidian rule: syntax shows when the caret enters it): headings, emphasis, lists with a space rule, tasks, quotes, footnotes, links. Inside `$…$` / `$$…$$` source no marker is hidden and no element is styled: a `**` is never bold, `==…==` never highlighted, a `[a](b)` never a link, `` `c` `` never code and a `[^1]` never a footnote reference — all of them are characters of the formula, in one font, one colour and one weight, whatever the theme does with a link or a code span outside it (7, 11)
- [x] Inline file title that renames the note — the ✓ costs one awaited call: the note is never held read-only, the save is chained to the move (so one made mid-rename lands on the new name, never the old one back to life), and a second ✓ waits for the first move instead of racing it
- [x] Tight character-level selection highlight, clipped between rows so neighbouring highlights meet at the midpoint between them — no gap, no overlap; roomier 1.85 default line spacing. Select-all and widget-heavy lines stay robust: widgets are never painted (the file title included) and rows fall back to the caret geometry when text runs can't be measured (13). Ctrl/Cmd+A selects the whole note even when the note itself hasn't got the focus (a tap on the title or the app chrome leaves it on the page); a field with its own select-all — the find bar, settings — keeps it (9)
- [x] Keyboard toolbar 8px above the keyboard, scrolling like Obsidian's (undo/redo, heading, lists, to-do cycle, footnote, math, delete line, new line below, move line), and a round hide-keyboard button beside it. "New line below" is Enter at the end of the line — it continues a list with the writer's own number, carries a to-do line's checkbox, continues a quote and reveals the marker — never an empty line under the text, and the same chain the Enter key runs, so the two cannot drift apart
- [x] Context-aware pairs: brackets, quotes, backticks, `$`, `*`, `_`, `=`, `~`, `%`; code, math, escapes and existing closers are distinguished. Keyboard and math toolbar share the same policy. `$$` on an empty line opens a math block; only tracked empty pairs are deleted together.
- [x] Markor's keyboard: word auto-correct and the suggestion strip on, no spell-check underlines (red squiggles) or writing-suggestions underlines anywhere in the note
- [x] The keyboard talks to the note's own text, not to Chrome's EditContext API (`EditorView.EDIT_CONTEXT = false`, the switch CodeMirror keeps for exactly this): on Android the WebView has EditContext, CodeMirror hands the caret to it, and the caret then leaves the DOM selection — so the WebView's own double tap and "Select all" have nothing to select, the suggestion strip and auto-correct never come back after a backspace, and a tap on a word is invisible to the IME. With the plain editable region the keyboard, the selection handles and the selection bar all act on the text the note actually has (APK 3, 4, 6)
- [x] Double tap selects the word under the finger and a drag before the lift takes in more (APK 5), as a fallback and never over a selection the browser made itself: `src/touchSelection.ts` holds the word rule (letters, digits and underscores, either script) and the tap counter on their own, testable without a touch screen; a tap on a widget or with a second finger is never a tap, and a tap below the last line still means the end of the note (APK 6)
- [x] ~~A space rule before closing brackets and punctuation~~ — decided against: the editor never second-guesses a space (typed or sent by the keyboard's auto-correct); the rule that dropped one before `)` turned out to be more trouble than it was worth (10)
- [x] Discord-style timestamps: `<t:UNIX>` and `<t:UNIX:FMT>` in all seven formats (t T d D f F R), formatted with `Intl` in the device's own locale; the relative form ticks every second while the app is visible, and the chip keeps its grey background on paper as it does on screen (src/timestamps.ts, src/markdown.ts, src/livePreview.ts, src/print.css)
- [x] Math source styled like Obsidian (the content between the dollars is monospace, italic; the dollars themselves keep the note's font in the accent colour — a `$$`-only line is never monospace), never rendered while editing. Only a `$$ … $$` pair whose dollars sit on different lines is a display block (the empty writing line included); `$$$$` / `$$ $$` with nothing between, a lone unpaired `$$`, and a pair a heading, a list item, a quote, a rule, a footnote definition or a fence broke are plain text — their dollars are ordinary text and nothing between them is styled as math. One policy (src/mathScan.ts) answers that question for the editor, the reading view and the note's direction alike, so the three can never disagree (11, 12)
- [x] The arrow keys are **one position a press, in the paragraph's own order and on the line's side** — the rule the platform's own fields follow, and the fix for the inline-math caret: in an RTL paragraph the visual right is the *previous* position, so → mirrors exactly as it does in a text field, and a shift+arrow grows the selection one character at a time. The walk it replaced stepped by *drawing* position, and the two faces of an inline formula share slots, so a press just after `$a^2 + b$` swallowed the whole run and the `$` signs were not stoppable. Math needs no case of its own — a line that is nothing but math or code is LTR by the direction policy (src/direction.ts), so display math reads and moves left to right whatever the note says. The two keys are read from a capture listener on the editor element rather than a keymap, so they answer while an IME composition is open, which is the state Gboard holds a word in (3, 7, 17)
- [x] ~~The line-number gutter moves to the note's majority side~~ — decided against: the line numbers keep the left edge, like every editor, and the file name with them. A gutter that changed sides with the note's language was more to explain than it was worth (10, 13)
- [x] Math digits (Settings → Editor): formulas show all their digits in one set — as typed, English, or Persian — in the preview and the PDF alike, and the note keeps the digits that were typed (5)
- [x] Switching between editing and reading keeps the same place: the mapping measures the rendered math and table heights and re-measures as they settle (fonts, the Android grow-box pass, images), compensating the scroll (9)
- [x] Footnotes: insert at the caret, write the note in a popover at the reference
- [x] Wiki links `[[Note]]`, `[[Note|text]]`, `[[Note#Heading]]`: styled in the editor, tap to open, a popup of notes while typing `[[`; broken links dimmed in the reading view
- [x] Images in the reading view and the PDF, centred and at most the text's width: `![alt](path)` relative to the note, `![[name.png]]` found anywhere by name (as Obsidian), optional size `|300` or `|300x200`; a dashed placeholder for a missing picture
- [x] `==Highlight==` as in Obsidian (editor, reading view, PDF)
- [x] The note always has room under its last line: the page scrolls a good deal further than the text, and a tap below the last line puts the caret at the end of the note. The room is for the writer's own scrolling — typing never spends it: the caret walks down through it, and the page moves by a line at most, so writing at the end of a note does not slide the text away under the caret. Enter reveals the line it opens, in the room the note already has (16, 20, 22)
- [x] Undo history per note (never undoes into the previous note)
- [x] Heading folding in the editor and the preview (chevron at the end of the heading line), fold/unfold all, remembered per note. A fold at the foot of a note keeps the reader's place: the height it takes is lent back to the page for as long as the reader stands on it (`src/foldSlack.ts`, `--fold-slack`), the scroll is put back in the same frame, and opening a title there no longer runs to the new foot of the page
- [x] Find and replace in one bar: regular expressions ignoring case (`$1` in replacements), from the caret, every match highlighted (a setting), a chevron drops down the replace row; the count sits where the query ends (on the left, in Persian digits, for a Persian query)
- [x] Keeps the caret clear of the keyboard without jumping or locking the scroll

Preview
- [x] Ordered lists keep the number the writer typed — a `۲.` is `2.` in the reading view and the PDF, never normalised to `1.` — while the writer's own `1.` starts a fresh list (19). In the editor the numbers *after* an edit follow it: Enter numbers the new item after the item above it and moves the numbers below only as far as they must — each has to be bigger than the one above it, so `6.` then Enter gives `7.` and a following `8.` stays `8.`, while `1. 2. 3.` becomes `1. 2. 3. 4.` — and a line that leaves the list (deleted whole, joined upwards, or emptied) brings the numbers below down by the number of items that went, checked on every edit rather than only for the toolbar's delete-line button. Editing an item's text moves nothing. A blank line, prose, another list or another marker ends the run, a nested list numbers itself and is stepped over, and a note being opened or a list being pasted keeps its numbers. An item already waiting empty on the next line is entered rather than duplicated, so nothing below it moves, and a to-do line continues with an empty box whatever the line above says (19, 12, 13, 15). An item pasted onto a line that already holds an empty box replaces it, box and all — the item's text, its own box state (`[x]` comes over done) and the line's indent — and the rule is a transaction filter, so it holds however the keyboard delivers the paste: Gboard's own clipboard hands the WebView an ordinary input change with no paste event behind it, a no-break space reads as a space, and a note being loaded or rewritten by the app carries no user event and is left exactly as it is
- [x] Reading view: sections tagged with source lines, KaTeX with balanced math line breaking (first at the writer's line ends, then commas, then relations repeated on continued lines, then at spaces typed between words, including inside `\text`; never at + or −; a group in plain parentheses or brackets is a step behind all of these, so a group that fits is never broken and one too wide breaks inside itself at its own punctuation instead of at an arbitrary atom) (8), inline math kept left to right inside Persian text, dollar signs in code left alone, code highlighting and copy, tables, footnotes in popovers, title on top. KaTeX's SVG signs (\vec arrow, stretchy brackets, roots) move with their letters under Android's text scaling: the sign is first sized in CSS ems, and where a painted box still misses the em it should have, the measured pixels are pinned and, only if even that is ignored, the sign is scaled as drawn (APK 1, 2); Persian inside a formula reads right to left in every case — a `\text{…}` run, and equally a word written bare, or inside a fraction, a root or any other command — while the formula itself stays left to right. A Persian phrase stays one run rather than one box per word: separate boxes are laid out left to right and the phrase came out backwards (23)
- [x] Edit/preview switch keeps the position; double-tap the preview to edit
- [x] Rendered only when visible (about 14x faster typing on long notes)

A tab button with the count (the digit centred on the icon's own centre, trimmed to cap height rather than centred as the line box it is drawn in), the full-screen switcher (note previews in two columns, close, "+", "N tabs" menu, Done, press and hold a card to drag it to a new place), an empty tab page ("No file is open" with recent notes), swipe a card away to close, reopen closed tab, kept across restarts. **Launch on start follows the writer's choice**: restore the last tabs, always open a new empty tab, or open one after being away for a chosen time (5 minutes to one day, 30 by default, the time row shown only for that choice — "Never" is gone). The last tab can be closed (the empty "No file is open" tab is what is left), the switcher's "N tabs" menu closes them all at once, a card's swipe takes its tab out of the switcher at once (the list re-renders after the close finishes, not 180ms into it), opening a note that is already open switches to its tab (from the new tab page too, leaving no empty tab behind), and the same file opened again from another app reuses the tab it already has — matched on the plugin's own source id first, then on the file's name, size and modification time, and a share on the text itself, since a file manager is free to vary the URI between hand-overs and shared text has no view id at all
- [x] Left sidebar: filter by name (found files and folders, flat, with their folder); Obsidian-style file tree of the space (folders open in place, sorting, the open note highlighted — and only the open one: the tree is redrawn when the drawer opens if the note changed while it was closed), long-press menu (new note/folder, rename in place, move, delete, use as a space, **Open all notes in tabs** in alphabetical order, **Replace tabs with this folder**), floating action buttons. Every file opens. **Always show the current file** sits in the drawer's own footer row, next to new note (on for a reader who has never touched it, remembered): the tree opens every folder above the note and scrolls its row into view, however the note changed — a tab, a link, a hand-over, a rename —; in "All files", it moves the walker to the note's parent folder. Off, the tree or walker's folder is left where the reader put it. The header's counts — the space's files and folders, or the walked folder's entries — have a line of their own under the path, and a name or path long enough to need it wraps to two lines instead of pushing the counts out of the header
- [x] "All files" walker (Markor-style): only the current folder, ".." to go up
- [x] Space switcher (vault-switcher style): spaces are shortcuts to folders; their notes are ordinary files, edited in place. "All files", add or remove a space
- [x] Bottom-sheet menus in Obsidian's phone style
- [x] Settings page (gear in the left drawer): theme, font size, line spacing, line numbers, highlight every match, which toolbar buttons show
- [x] Android back button, Obsidian's order: menus, popovers, the tab switcher, settings and the find bar close first, then the drawers; then "Press back again to exit." (a second press within 5s leaves the app). Works in the browser too, through the page history
- [x] UI chrome can't be selected as text; only the note, footnotes and fields can
- [x] Per-file reading memory: mode, fractional source-line position, caret and folds survive tab closure/reopening and app restarts; late font/image/scroll callbacks are cancelled on navigation or reader intent. Incoming Android files use a stable URI bookmark identity, not their temporary grant ID.
- [x] Session-only per-tab undo/redo: switching tabs or losing focus preserves both stacks; actual tab/app closure discards them. External text reloads remain undoable; no persistent revision manager.
- [x] Shared contextual direction inference in editor, preview and PDF: first strong prose; unanimous preceding section before neighbours; preceding prose breaks a mixed tie; headings are boundaries. Digits are neutral, math/code never vote and remain LTR. Full-document editor context is cached independently of the viewport. A line with no letter of its own — a bare number, a date, a `#`, a list marker — continues the line above it whatever the note's majority says, so an English headline never turns the Persian line under it around (18). Blank lines between display-math blocks and between fences take their neighbours' direction, not the prose above them, so an empty line between two `$$` puts the caret at the left where the typing happens; and a `![alt](path)` — like any link — whose label carries no letter of its own is isolated whole, `direction: ltr`, so a picture's markdown ends where it is written on a Persian line (a Persian label keeps the line's direction and only its address is isolated)
- [x] Cold start: the last screen is painted from a copy before the app's code has loaded, then the real app takes over underneath. On Android the system splash stays on screen until the web app has booted (`SplashPlugin` → `setKeepOnScreenCondition`, called 700ms after the cover is lifted, with a 5s safety), so the cover's removal is not seen as a second animation. One of the claimed fixes PLAN.md carries — the writer's check on the device is what settles it

- [x] Storage layer behind one interface: a web backend (localStorage, as now, for development) and a native backend (device files)
- [x] Spaces: a space is just a folder path saved in the app's own settings. Nothing is ever written into the folder (no `.obsidian`-style config). "All files" is the storage root.
- [x] Rename, move and delete; view memory and history keyed by path (real files: verify in the APK)
- [x] Autosave to the file (debounced, flushed on background, on a file switch and on the way out of the app); the modification time is checked on resume and again before every save, and a file that changed underneath — or vanished — raises the app's own card ("File changed elsewhere" / "File missing") with reload-or-keep, never a silent overwrite.
- [x] Reopen the last tabs on launch; a note that's gone falls back to the first note in the space
- [ ] Search index per space (read files lazily, cache the text, refresh on modification time)

- [x] ≡ menu in the bottom bar, as Obsidian's ribbon menu: collapse / expand all headings, reading / editing view, Export to PDF, rename, delete note, settings. Settings → Navigation bar → Menu button picks a quick action: a tap runs it (its icon, with a small chevrons-up-down flair), holding opens the menu
- [x] Export to PDF straight to Android's print dialog (as Markor), where "Save as PDF" writes the file under the note's name; in the browser, the browser's print dialog
- [x] The look: Vazirmatn 15px at 1.8, never justified, each paragraph in its own direction; headings 1.6 / 1.4 / 1.25 / 1.1× in bold with Markor's rule under h1 and h2, kept with what follows; tables centred as in the reading view; code in a light grey box with the preview's colours; blue underlined links (clickable in the PDF); wiki links as plain text; task boxes as in the reading view; no title on top
- [x] Per-file export options in Settings → PDF export (beside page numbers and CSS, not an export popup): one or two columns, centred or reading-edge display math, and automatic/prose-majority or explicit LTR/RTL reading order. Preferences stay in the app, follow file/folder renames and never rewrite Markdown. Two-column layout paginates at column width, then pairs columns onto A4 without scaling text.
- [x] Stranded-heading protection at page/column boundaries (Paged.js overflow hook); consecutive headings travel with following content rather than being left alone at the bottom.
- [x] A4, 1in margins; page numbers at the bottom centre, 12pt, in Persian digits (Settings: Persian / Latin / none)
- [x] Footnotes at the foot of their page (Paged.js), numbered from 1 on every page, under a short Word-style rule on the start side; the call's digits follow its paragraph, the note's its own text
- [x] Long formulas wrapped at the page's width by the same rules as on screen
- [x] Page breaks: `\pagebreak`, `\newpage`, `\clearpage`, `<!-- pagebreak -->`, `<!-- newpage -->`, or any HTML with a page-break style (`page-break-before: always`, `break-after: page`…); hidden on screen, ignored inside code
- [x] Custom CSS (Settings → PDF export), applied after Satr's own; per-file math alignment and fixed two-column page geometry take precedence
- [x] Fonts (Vazirmatn, Vazir Code, KaTeX) embedded as data URIs; Paged.js (≈500 KB) loads only when exporting
- [x] The font-scale override that used to be applied while measuring is gone — both WebViews are pinned at 100% text zoom now (see Text size, under the APK phase), so nothing has to be cancelled before printing. It had to be an adopted stylesheet rather than a `<style>` back then: Paged.js takes every style element out of the document and copies its text into the stylesheet it prints with, which once divided every font size in the PDF by the phone's scale and made it tiny
- [x] Images embedded as data URIs, centred, never split across pages
- [x] The pages handed to the app's print WebView are pinned to the A4 geometry Paged.js measured, and that WebView views them at the paper's width: Paged.js's own `@media print` rules tie `html`, `body`, `.pagedjs_pages`, `.pagedjs_page` and `.pagedjs_sheet` to 100% of the print viewport, and the print WebView has the phone's, so every sheet was clipped to the screen's height and the body was capped at its width — the bottom of each page, and in two-column mode the whole second column, never reached the paper. The browser's dialog was never affected (it prints the export iframe, which is A4-tall), which is why only the app's PDFs were cut. Paged.js's letter-sized `@page` is overridden with A4, no margins, as the last word in the cascade; the spent `<template>` and the scripts go out with the string
- [x] On-device check of the print path (fonts, links, page size), including the two-column layout — tested in use on the device

### The APK round: six reported issues (September 2026)

Reported on the installed APK; the site and the PDF were fine, so the fixes are in
the Android WebView path and the print path is untouched.

- [x] 1. `\vec{u}`'s arrow touched the `u` in the preview while the PDF was right. A painted box that missed its em was corrected, measured against the formula's own font size, not the note's (tests/mathSigns.spec.ts measures a frozen box with the text at scale and the sign not). The root cause was the WebView's text zoom (see Text size, above); the painted-box correction stays as a safety net for a WebView that still mis-resolves em.
- [x] 2. Signs (arrows, stretchy brackets, roots) did not scale with the system font size although the letters did. Root cause: text zoom scales the glyphs without the em context the signs are laid out in; the whole sheet is derived from the phone's scale in CSS now (see Text size, above).

- [x] **A fence is coloured by its language, a formula by its parts, and both from one palette.** Source mode fetches a CodeMirror language the first time a fence of that language is seen and colours the fence in place; the reading view and the PDF keep highlight.js, which already had them. The two had drifted into two sets of colours for the same code, so there is now **one palette, the preview's**, mapped onto the editor's token names — seven hues, which was the point: a fence is colourful because a language has many *kinds* of word. LaTeX has them too, but they are in **which command it is**, not in the token's name, so a backslash word is sorted by what it does: scaffolding (`\begin \end \left \right \displaystyle`) as a keyword, a command that takes something (`\frac \sqrt \sum \int \text`) as a function, a command that *is* something (`\alpha \infty \to \leq`) as a value; the words inside `\text{…}` and the environment `\begin{…}` names as a string; numbers, variables, `_ ^ & \\`, the operators, the braces and a `%` comment on Obsidian's own map, read out of its `app.css`. - [x] **A formula KaTeX cannot read says so, in colour, the moment it is wrong.** Obsidian does not do this half at all. A spec sweeps every caret offset in a broken formula and fails if any of them hides the mark.
- [x] **The complaint is said at the top of the screen, in the fewest words that still name the thing to fix.** Three attempts at where it goes, and the rule that came out of them is that **no caret position may ever hide the complaint**: the bottom bar is where the hands are, so a line written at the bottom of the screen ends up behind the very complaint it caused, and the answer is to move the warning, never to scroll the writer's text. - [x] **The bars follow the reader's hand, and the beat is the slide itself.** The fixed 200ms beat of the last round was a guess at how long a bar takes to move; it is now the bars' own `transform` `transitionend` that lowers the gate, with a stale-event guard (a foreign target or property, or an event inside 16ms of the slide starting, is ignored) and a computed backstop for the event that never comes. A turn of the hand is seen as a turn (`HAND_TURN`), not as noise, and the trace behind `?bars=1` is what made the slow upward scroll on the phone legible in the first place.
- [x] **A long formula breaks where a reader would break it — measured on 5 296 real formulas, none of them invented.** Two corpora, both rendered into a 340px column, a phone held upright: 4 477 formulas scraped out of Wikipedia's maths and physics articles, and 819 out of the author's own university notes. Before: Wikipedia painted 294 formulas past the edge of the column and handed 168 of them back to the browser whole; the notes had 36 off the screen, 5 408px of overrun between them, the worst single line 552px past the edge. Three defects, in the order they were found. **`+ − · ×` were not break points at all**, so a long sum was cut into "everything" and "= 0" and "everything" went off the side; a sum may now break at its own operators, last of all, after line ends, commas, relations and word spaces, and the operator ends the line rather than opening the next one, because a line that opens with `+` reads as a sign. What is left is five formulas too wide inside a single `\frac` or `\sqrt`, which cannot be broken without rewriting the mathematics, and three aligned blocks. The cost is about 0.23ms a formula. tests/mathBreakCases.spec.ts holds 44 awkward formulas written by hand — decimal commas against list commas, `1,000,000`, `x,,y`, `a، b`, Greek typed straight in, a lone `+`, `a +` — with the shape each one should take, and four rules beside them: no line begins with the operator it was cut at (KaTeX's own `mbin` tells a binary from a sign), a relation is repeated on the next line and an operator is not, every piece balances its delimiters, and the writer's own layout is never opened up.
- [x] **A formula's spaces are TeX's spaces.** The kept-space feature is gone, at the author's word: `$a b$` and `$ab$` render the same, as they do everywhere else LaTeX is read. Words come from `\text{…}`, whose spaces are kept and are also the second-best place to break a long line, and a run of Persian is still wrapped in `\text{}` before KaTeX sees it, so its spaces survive by the same rule. - [x] **Two lists that follow one another are two lists.** Reported: `1. 2. 3.`, Persian, parentheses, letters — one kind of list written under another arrives as a single list, labels right, no gap between the halves. The cause is in how the numbering works at all: every marker is rewritten in Latin digits before the parser sees it (`۱.`, `الف.` and `a.` all arrive as `1.`), and then drawn back from the source line afterwards — so to the parser a Persian list under an English one is simply more of the same list, exactly as `1.` under `2.` would be. The two Persian orders count as one kind (a `ب` is the second letter of both, so no single marker can say which order it is in — the list settles that from all the letters it holds), upper and lower case count as two, and an item with no marker of its own stays with the run above it. ### The 0.8.2 round: the formula that arrived in the wrong dialect (October 2026)

A note pasted from Pandoc, remark-math, a LaTeX tool or a chat assistant carries its formulas as `\(…\)` and `\[…\]`. Satr speaks `$…$` and `$$…$$`, so those formulas were showing as the plain text they are, with nothing in the note to say why.

- [x] **The note says so, and the bar is the fix.** The bar under the note grows a row of text above its own buttons — `⇄ 6 LaTeX-style formulas — tap to convert` — and a tap converts. Nothing is added to the top of the page and no line of the note's own is taken: the gray is out of the flow, tucked up behind the pill, with only its top rounded and the white pill untouched above it, in the same place. The **≡ sheet** offers the same thing, greyed out when there is nothing to convert, and the keyboard toolbar's own pill carries it while typing. It cannot be dismissed: a note that needs converting says so until it has been converted. After the tap the bar is the receipt — `3 formulas converted` — and then it is a row of buttons again.
- [x] **Only paired delimiters are rewritten, and one undo puts the note back.** A lone `\(` is far more likely a CommonMark escape than half a formula, so it is left exactly as typed; `\[…\]` may span lines, and a heading, list, quote or fence between the halves breaks the pair, as it breaks `$$`. Code is never math, and a pair whose content already carries a dollar is skipped, so dollars can never nest. The whole rewrite is one transaction, so one undo returns the note exactly as it arrived. The scanner (src/mathScan.ts) stays dollars-only, which is why the reading view, the PDF, print and the direction of a note needed no new case at all: after the rewrite there is no `\(…\)` left to disagree about. tests/mathNormalize.spec.ts (17): the escapes stay, the code stays, a second run finds nothing, a pair that spans lines becomes a block, the receipt outlives the animation that would have taken it, and the bar grows without moving the pill.
- [x] `package.json` and the lockfile's two root fields carry **0.8.2** (the dev banner's number matches the app's, as it must).

The race is gone: Blink's SelectAll dispatches a cancelable `selectstart` on the editable root *before* it moves the selection, so the editor answers it there (the platform skips its own step for a canceled event) instead of reading the result afterwards. That result was the problem: for an element-level select-all the platform can leave a *caret* at the note's end — which is exactly what CodeMirror then copies down — and which of the two won decided whether the command had worked. A finger or key that was busy in the editor a breath ago is exempt, so a selection made by hand is never taken for a command. tests/selectionRows.spec.ts pins it (9 tests)

Four follow-ups came out of a second diagnosis of the same round, and are in:

- [x] A focus arriving on its own no longer glides the note back to the caret. The WebView re-focuses the editable region by itself — a checkbox tapped further down the note, a link, the keyboard restarting — and the focus handler brought the caret back into view each time: measured, up to 1688px of jump for a tap the writer never meant as a caret placement. Only a caret that actually moved is brought in now, and a command that selects the whole note (whose head sits at its end) leaves the view where the writer was. tests/editorDetails.spec.ts
- [x] The platform's *other* shape of "Select all" — the one that resolves against the page instead of the note, because the note is not what the WebView thinks is focused (Blink's hidden-selection case) — means the note here too whenever the note is on screen: the range is rewritten text-anchored and the editor adopts it. A field's own selection, and the reading view's, are still left alone. tests/selectionRows.spec.ts
- [x] The tab card is a picture of the note, so it shows the note at the note's own text size (`--note-font-size`) rather than whatever the app chrome uses. tests/tabSwipe.spec.ts
- [x] A measured length cannot reach the paper unnoticed: tests/printApp.spec.ts now asserts that the handed-over document's math carries KaTeX's own em sizes and no frozen px — the one way a size measured in the app's frame could arrive at the print frame already wrong. It does not: the same formulas measure the same in the app's PDF and the site's, to 0.01pt.

Measured side by side against Obsidian 1.12.7 mobile at 390×844 and matched: editor (16px / 1.5, 60px top spacing, 24px side margins, 700px line width, line-level headings with Obsidian's sizes, weights, line heights and letter spacing, list and checkbox geometry, 14px code), reading view (heading, paragraph, list, blockquote, code and table spacing), bottom bar (52px pill), header (44px buttons), left drawer (space switcher at the bottom where Obsidian has its vault profile, "N files, M folders"), Settings (cards, rows, dropdowns, toggles) and the ≡ menu sheet. Known traps (worth remembering)

- [ ] Async widgets in CM6 aren't natural. Write the placeholder-then-update pattern once, reuse it for math and mermaid.
- [x] Offscreen WebView for printing must be attached to the window, or images and fonts render inconsistently.
- [ ] onPageFinished doesn't mean "content is ready." Use an explicit signal. (Print sidesteps it: static, pre-laid-out HTML.)
- [x] Paged.js in a right-to-left page silently drops text: it looks for overflow to the right, but RTL columns grow to the left. The print page stays LTR (each paragraph has its own direction), as the reading view's article does.
- [x] IME inside a WebView is a known weak spot. The typing recipe from markdown-editor is the mitigation, and it is what the app has run on the device since 0.7 — Persian and Arabic composition have been in daily use.
- [ ] The last-opened file can vanish between sessions — stat it on launch, fall back to the browser.
- [ ] Autosave can clobber external edits — that's why mtime-on-resume exists.
- [ ] Live preview tables as pipes is way cheaper than as a widget. You already chose pipes, which is the right call.
- [ ] GFM has no footnotes — resolved by the footnotes plugin, worth remembering when the flavor question resurfaces.
- [ ] CM6 state lies if you ask the DOM: `view.lineWrapping` is a measure pass behind, so wrap/gutter state must be tracked as your own flags, and a hidden pane needs `requestMeasure()` before it measures correctly.
- [ ] KaTeX emits `style` attributes in places (array and rule sizing), and the ported DOMPurify config bans `style` outright. Verify KaTeX's output survives sanitization — if it doesn't, allow `style` only on `.katex` descendants via a sanitizer hook, never globally.
- [ ] Mermaid is intentionally postponed; do not reintroduce its dependency or renderer until a later phase.
- [ ] CM6 does not run under jsdom (it throws in `measure`), so editor tests belong in a real browser/device suite, separate from `node --test`.
- [ ] Two equally-specific `!important` rules race on load order, not specificity: the markdown-editor repo shipped a hidden-editor bug for months because `[hidden]` and `.editor-pane` both declared `!important`. Don't use `!important` for layout state.
