## source mode and the reading view

- [x] `۱.` was not a list marker in source mode **anywhere** — *(found here, auditing where a marker may legally stand)* *one row per context, both scripts, read off the editor itself: on its own line, indented, nested under a bullet, with a paren — `1.` got the list line and the hanging indent, `۱.` got neither, only a dim the editor painted on it by hand. Inside a quote neither script got them, in any language. A table cell gave both of them nothing, which is right and is not a gap: markdown has no block lists in cells, so `1.` is prose there and `۱.` is prose with it. The cause was that the editor held **three** separate ideas of a list — the markdown parser (ASCII digits only, but it knows every place a list can sit), a regex that dimmed what the parser could not read, and the numbering and Enter rules, each anchored to the start of a line with no room for a `>`. The parser reads the numbers now: it is handed the writer's own text with Persian and Arabic-Indic digits folded to ASCII, one character for one character, which is exactly what the reading view has always done before marked sees a line. So the layout, the gutter, the fold, the numbering and Enter all follow one definition again, and every row of that audit is now identical between the two scripts.*
- [x] `الف.` and `الف)` get dimmed with nothing but a space in front of them, while `a.` and `a)` wait for a `b.` — a double standard — *one rule now, in both scripts and in both views: a letter is a marker where the line above or below carries the next or previous letter at the same indent. English had the rule for a reason — `A. Smith` is a name, not a list — and Persian has the same sentence in it, `م. شاکوری`, which used to come out as a list. The letter-after-letter test was a character-code step, English-only by construction; it asks the alphabet now (ابجد or the Persian order, with `الف` and `ا` as the one first letter), and a letter is never the neighbour of a letter from another script. **What changed for you:** a lone `الف. اول` with nothing under it is a sentence now, where it used to be a one-item list. If you would rather have it the other way — both scripts becoming a list on sight — say so; it is the same one function.*
- [x] a list with a blank line written into the middle of it arrives as one unbroken block — "*such a thing becomes one really weirdly*" — *two separate faults, both closed. **The air:** the parser already knows a list whose items are separated by blank lines is loose, and says so by giving every item a paragraph of its own; the stylesheet then zeroed those paragraphs' margins — Obsidian's own rule, and Obsidian does draw a loose list exactly like a tight one — so the gap you typed was worth nothing on the page, under numbers, bullets and checkboxes alike. The first fix hung the air on the whole list, the way the parser reads looseness, and you sent it back — *“you added space between list items, the bullet ones, which is undesired… make it match source mode”* — rightly: one gap anywhere in a list pushed **every** pair in it apart. The air belongs to the item you left room above, and only to it: an item with a blank line over it, and an item above it to be parted from, carries one line of your own text as room. Measured at 390×844, source against preview, text to text: three items, a blank line, two more steps **32/60/32** against source's 32/62/32, where the list-wide version stepped a flat 46/46/46; a list written line under line steps 32/32 in both views; a list with a gap at every pair steps 60/60 against 62/62. Inside a quote, `>` and `> ` are the blank line. The list stays one list. **The numbers:** an English list is drawn by the browser's counter, which counts whatever is written, while a list in any other script was drawn here item by item from the marker on each line — so one note numbered its two halves by two different rules, `۱ ۲ ۳ ۵ ۶` keeping your numbers and `1 2 3 5 6` quietly becoming `1 2 3 4 5`. - [x] a lettered list — `a.`, `الف.`, `ب)` — gets no list layout in source mode, in **either** script — *(found here, closed on your ask: “for letter lists both systems, it would be so much better”)* *the same audit's last open row. ## note lint criteria

for the in-app lint/fixer above, measured on term_three with the app's own scanner (0 katex errors today, everything else is real):

1. a display `$$` line that is a lazy continuation of a list item — it renders inside the bullet, indented and centered within the `li`, instead of as a page-centered display block. 11 sites now: Probability Theory 03:83,86,89,92,95,121,124,127,130; Mathematics 2 03:32; Linear Algebra 01:18. fix = one blank line before the `$$`
2. `<div dir=ltr>` wrappers are now redundant (direction is computed, math is already forced ltr) — 20 pairs in Mathematics 2 01, all paired, safe to strip. report as "redundant", not "wrong"
3. trailing `:` in a heading, visible in the outline and in search — Accounting 03:5 `## فصل دوم: `, Accounting 03:66 `##### اهداف:`
4. trailing space in heading text, so the outline reads `معرفی ` — Accounting 01:14, Linear Algebra 02:21
5. list indent must be 0/2/4: a 1-space indent reads as a sibling rather than a child, so a bullet that looks like a parent renders as a peer — Probability Theory 02:246
6. empty list item renders as a blank bullet — Probability Theory 01:159
7. run every formula through `renderMath` and fail on any `katex-error` — katex is `throwOnError: false`, so a typo is a silent red formula in the reading view and in the PDF, and there is no other way to notice
8. assert the latex-style converter never fires on a real line break: `\\[6pt]` in Linear Algebra 03:38 is a `\\[6pt]` skip, not a `\[…\]` pair. today correct by two independent guards (the preceding backslash, and the enclosing `$$` span) — worth pinning so neither guard is ever weakened

not criteria, deliberately: callouts/dataview/graph/tags (not supported, would render literally), table separator styles and headerless tables (`ensureTableSeparators` inserts the separator, then the empty header row is removed), persian `۱.` ordered lists (transliterated, then re-rendered as persian), bare emails (gfm autolinks them), math digit style (a settings choice), and unifying `$$ x $$` against bare `$$` (both are `display: true`, they render the same)
